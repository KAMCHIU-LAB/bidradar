# 运行说明

## 常用命令

| 操作 | 命令 | 是否调用AI |
|---|---|---|
| 采集全部来源 | `python3 bidradar.py collect` | 否 |
| 重试一个配置来源 | `python3 bidradar.py collect --source <来源ID>` | 否 |
| 生成并独立复审简报 | `python3 bidradar.py brief` | 是；当前成稿及复审均命中缓存时为零 |
| 重新保存阅读预览 | `python3 bidradar.py digest` | 否 |
| 检查篇幅、引用、评分和复审 | `python3 bidradar.py quality` | 否 |
| 查看采集、预算与投递状态 | `python3 bidradar.py status` | 否 |
| 搜索本地资料 | `python3 bidradar.py search --query generative` | 否 |
| 查看逐篇初筛归档 | `python3 bidradar.py library` | 否 |
| 逐篇初筛 | `python3 bidradar.py review --limit 2` | 是；仍受每日预算约束 |
| 完整处理当前窗口 | `python3 bidradar.py run` | 是；可能发送通知 |
| 检查周期并执行到期任务 | `python3 bidradar.py scheduled-run` | 到期后可能调用 |
| 解除定时任务 | `python3 bidradar.py uninstall-schedule` | 否 |

`brief`、`digest`和`quality`默认重新打开最近一次调度窗口，便于复查同一份简报。`run`处理当前窗口并绕过周期日期限制。

## 预览和依据在哪

运行目录：`~/Library/Application Support/BidRadar/`。

- `digests/<日期>-preview.md`：阅读版，只包含简报正文。
- `digests/<日期>-sent.md`：当天实际发送内容的归档，不被预览覆盖。
- `reviews/<日期>-evidence.md`：候选取舍、评分依据、短引文与采集状态，仅留本机。
- `quality/<日期>.json`：结构、篇幅、复审和调用记录。
- `radar.sqlite3`：采集缓存、审核历史、预算、周期与通知状态。

macOS可以在访达中按 `Shift + Command + G`，粘贴上述运行目录。配置单独位于 `~/.config/bidradar/config.toml`。

阅读版先给本期看点，再分重点阅读、值得跟进、旧文补读，最后汇总公司动态。每条包含具体阅读用途，计入100字。新增模板或内容会使旧版批准失效；新成稿需要重新复审，历史实际发送归档保留原样。

## 调用预算

自动周期与每日均最多6次模型调用，两个上限同时生效，失败同样计数。默认不做额外逐篇初筛。启用时最多2篇，须为生成、复审、一次修订及再次复审预留4次。

`brief --evaluation-calls 4`是显式的额外验收入口，使用独立的一次性持久预算；再次运行或跨日均不会刷新。只有在用户明确同意额外消耗时使用。`--fallback-model gpt-6-luna`仅用于该验收入口遇到额度错误后的尝试，失败也占名额。模型可用性取决于实际账号。

调用次数不能换算订阅剩余额度。程序不会自动增加预算，也不执行论文代码或训练实验。

## 来源失败怎么处理

先运行 `status` 查看来源ID，再用 `collect --source <来源ID>`单独重试。明确失效且无可靠替代的入口从配置移除；历史采集记录保留，不冒充本期更新。

RSS可能只保留很短的历史。每日缓存仅改善启用之后的覆盖，不能恢复此前已被挤出的文章。缺日期、达到分页上限或全文读取失败都会留下状态说明。

智源社区使用公开页面自身的匿名读取接口，没有稳定性承诺。公司关键词只负责召回，不证明作者所属公司。读取范围不足时须降低判断强度。

## 推送结果不确定怎么办

网络中断可能发生在飞书已经收到、客户端尚未收到响应的时候。程序将此类投递标记为“不确定”，不会自动重发。

先人工查看群记录，再执行：

```sh
python3 bidradar.py resolve-delivery --id <通知ID> --delivered yes
# 确认未收到时使用 --delivered no
```

确认收到后，只回放该次发送前保存的成稿，不把后来生成的预览当成已发送。当天已有成功或待核实投递时，自动流程跳过重发。

## 定时任务

macOS使用 `launchd`。安装后每天09:00检查，实际执行日期加15天作为下次到期日。重装任务不刷新周期。

失败周期在随后两天的09:00有限重试，沿用原窗口和预算。错过周期时默认最多回溯45天，仍受源站历史范围限制。状态“完成”表示本期简报已送达或没有可推荐内容，不表示行业资料完整。

锁屏可以运行；睡眠、关机或断网会影响执行。时间以电脑本地时区为准，安装时会检查与配置时区是否一致。
