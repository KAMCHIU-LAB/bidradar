# 实现与取舍

BidRadar给个人阅读队列提供可追溯的筛选结果。工程重点是约束输入、保留实验边界、审阅具体成稿，以及控制调用和推送的副作用。

## 模块职责

| 模块 | 职责 |
|---|---|
| `bidradar.py` | CLI、来源采集、配置与状态、模型进程、预算、飞书与macOS调度 |
| `research.py` | 主题与公司判定、研究归并、节选、提示词、评分校验、渲染与发布历史 |
| `*.schema.json` | 逐篇初筛、联合简报和独立复审的结构约束 |
| `reviewer.instructions.txt` | 把来源视作不可信数据，仅审阅提供的证据 |
| `config.example.toml` | 来源、周期、篇幅和调用上限的公开模板 |

运行依赖Python标准库、curl和AI步骤中的Codex CLI。状态使用SQLite，适合单用户、本机定时任务。

## 从来源到卡片

1. **采集与时间判断**：适配arXiv、RSS、精选GitHub仓库和社区文章。保留来源、发布时间/更新时间及日期依据；社区分享时间不冒充论文首发。
2. **候选与节选**：按出价主题筛选、保守归并相关URL，限制每篇及总输入长度，标记截断范围。归并不能覆盖所有“论文—代码—转载”关系，模型和复审仍需查重。
3. **联合成稿**：逐篇决定纳入、观察或暂缓；提供技术、成果、边界、阅读用途、分项评分和原文短引文。
4. **确定性检查**：检查字段、评分求和、门槛、引文逐字出现、篇幅和候选决策覆盖。引文出现不证明结论成立。
5. **独立上下文复审**：另一次模型调用只看到候选成稿和公开证据，检查数字、归因、新旧判断及遗漏条件。批准与候选内容哈希绑定。
6. **预览与投递**：通过复审后保存阅读版，评分理由和状态另存；飞书成功响应后才记为已发布。

生成与复审是独立调用，未必使用不同模型。两者可能出现相同偏差，不能代替人工阅读原文。

## 为什么保留这些约束

| 决定 | 解决的问题 | 代价 |
|---|---|---|
| 每篇100字、正文2,000字 | 快速判断是否打开原文 | 无法承载完整实验分析 |
| 含金量与相关性分开 | 区分研究价值与工作关联 | 编辑评分需要持续校准 |
| 缺证据可待评 | 不把未取得全文直接判为差研究 | 观察项需要后续核验 |
| 日期、归属与效果分开判断 | 避免转载当首发、关键词当认证、成本当收益 | 可能暂缓候选或产生空简报 |
| 复审绑定输入与具体正文 | 防止改稿后沿用旧批准 | 模板或内容改变会使缓存失效 |
| SQLite预算与投递记录 | 重启后保留调用次数与通知状态 | 并发受本机锁限制 |
| 不确定投递停止自动重发 | 避免网络超时导致重复通知 | 需要人工核对群记录 |

## 本地与外部的数据边界

源码、模板、公开样例和虚构检查资料进入仓库。运行配置与数据默认放在代码目录外：

- `~/.config/bidradar/config.toml`：模型参数、飞书凭证、来源设置。
- `~/Library/Application Support/BidRadar/`：缓存、标签、备注、成稿、预算与投递记录。

模型输入包含选中的公开资料、公开发布历史摘要和阅读标签，不包含私人备注。飞书接收通过复审的阅读正文。CLI在独立临时目录运行，禁用工具等扩展并检查返回事件；来源文本仍可能误导模型。

采集限制HTTPS与主机白名单，不使用网页登录态，不绕过登录、验证码或付费限制。支持的来源是有限范围。

## 调整研究范围

### 添加或替换来源

优先复用 `feed`、`arxiv`、`github_curated`、`baai_author` 或 `baai_search` 适配器。在配置中声明入口、条数和分页上限；新域名还要同步检查 `bidradar.py` 的 `ALLOWED_HOSTS`、`PUBLIC_HOSTS` 与重定向限制。

先确认日期、正文读取范围与归属依据，再判断资料是否适合推荐。公司关键词只负责召回。

### 扩展其他算法主题

仅换RSS地址不足以切换领域。还需一起调整 `research.py` 的主题判定、公司匹配、`prepare()`关注方向、提示词与评分锚例，以及来源召回词；保留“未知、待评、暂缓”的出口。

这部分目前需要修改代码，没有通用领域配置接口。

## 可靠性范围

默认每日与每自动周期各最多6次调用，两项上限均由 `[review].daily_limit` 控制；分别累计，达到任一上限即停止新增调用。首次成稿需预留生成与复审2次，最多再修订一次并重新复审；失败也计数。显式额外验收使用单独的持久预算。

飞书投递不是严格的恰好一次语义。网络中断后可能无法判断是否已送达；此时保留“不确定”状态，不自动重发。恢复时使用发送前的快照，避免把后来修改的成稿记成已发送。

当前没有多用户服务、跨机器部署、Windows、PDF全文分析或自动运行论文代码。来源改版、语义遗漏与漏报仍需人工跟进。
